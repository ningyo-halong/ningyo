# 人形ページの共有いいね

43体の各ページで、写真・名前・番号の下にハートと全員共通のいいね数を表示します。
来場者のログインは不要です。押すと赤いハートになり、同じブラウザーから同じ人形への
再送は1票として扱います。もう一度押すと取り消しになり、共有の数が1つ減ります。
取り消した後に押すと、再びいいねできます。案内文は表示しません。

## 構成

- GitHub Pagesは今のURLで継続します。
- いいね数はSupabaseのPostgresに保存します。端末内だけのカウンターは使いません。
- `likes.js`が表示を更新し、`likes-api.js`が共有データを取得・送信します。
- 画面を表示中は30秒ごと、画面に戻った際にも最新の数を取得します。
- 保存先から正常な応答を受け取ってから数字を増やします。エラーを「0件」に置き換えません。
- 人形IDは並び順ではなく元のファイル番号です。`16.html`の道成寺はID 16、
  `01.html`のアマビエはID 1のままです。並べ替えても票が別の人形へ移りません。

## 接続・公開

1. 展示用Supabaseプロジェクトに
   `supabase/migrations/202609300001_doll_likes.sql`、続いて
   `supabase/migrations/202610010001_toggle_doll_likes.sql` を適用します。
   既に最初のSQLを適用済みの場合は、2つ目だけを適用します。既存の数や票は維持します。
2. `likes-config.js`にプロジェクトURLと**publishable key**（`sb_publishable_`で始まる公開用キー）を設定します。
   `service_role`や`sb_secret_`で始まる管理用キーは絶対に入れません。
3. 別々のブラウザーで同じ人形を開き、いいね数が共有されることと、再送が重複しないことを確認します。
4. 接続確認後にGitHubの`main`へ反映します。設定が空の場合はボタンを表示しません。

SQLは票と集計を非公開スキーマに置き、外部には数の取得と、自分のいいね状態の設定を許可します。
以前のページ用の1票追加処理も互換性のため残します。
匿名のブラウザー識別子は一覧公開せず、票の削除や数の上書きも公開APIでは許可しません。
追加・取り消しは1回のトランザクションで行います。取り消した票は非アクティブとして保持します。
希望する状態を送ることで、応答が失われた後の再送も二重に増減しません。

ブラウザー識別子はランダムなUUIDです。氏名・メールアドレスは集めません。
ブラウザーのデータ消去や別の端末の利用では別の訪問者になります。
本人認証付きの投票ではなく、来場者の気軽な「いいね」を集める機能です。

## 検証

`npm ci` のあと `npm test` を実行します。Postgres互換のPGliteで本番と同じSQLを実行し、
別の訪問者間での共有、追加・取り消し・再追加、重複送信、応答が失われた後の再送、
票の分離、移行後の状態維持、公開権限を検証します。
テスト用の数はメモリー上のDBだけに保存され、本番へ送信しません。
